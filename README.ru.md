## ✨ Зачем это нужно

Wallaby (wallabytoken.com) — это работающий из Сиднея слой инференса, который перепродаёт передовые открытые модели за предоплаченные доллары США, и **каждый новый аккаунт начинается с $0.50 бесплатного пробного кредита** — без карты, без телефона, без пополнения. Сегодня каталог состоит из одной модели, **`kimi-k3`** (контекст 1M, постоянно включённое рассуждение), тарифицируемой по **$2.70 за вход / $13.50 за выход за 1M токенов** ($0.27 за кэшированные) — на 10% ниже официальной цены Kimi по прайс-листу.

Панель — это форк New API за **Cloudflare**, и Cloudflare составляет всю сложность: `/register` отвечает управляемым испытанием, а `POST /api/verification` и `POST /api/user/register` тоже защищены испытанием — так что ни один ключ не существует без браузера, который держит `cf_clearance`. Хуже того, испытание проходит только **видимый** браузер: измерено на тех же выходах в тот же час, headless прошёл **0/9**, а headful прошёл **3/3**. Именно поэтому этот инструмент управляет настоящим, видимым Chrome (README повторяет это, потому что запуск в headless выглядит точно так же, как сломанная панель) и поэтому один аккаунт стоит пару минут, а не секунду.

## 🎁 Бесплатный тариф — сколько вы получаете

| Что | Значение |
| --- | --- |
| Кредит при регистрации | **$0.50** — считано из консоли как `quota = 250000` (`quota_per_unit = 500000`, USD 1:1) |
| Карта / телефон | **ни то, ни другое** — адрес электронной почты + пароль + код из письма + проверка на человека |
| Срок действия | **никогда** («без карты · без пополнения · никогда не истекает») |
| Модели на бесплатном тарифе | **`kimi-k3`** (+ псевдоним `moonshotai/kimi-k3`); DeepSeek V4 Flash/Pro указаны как временно недоступные |
| Цена | $2.70 за вход / $13.50 за выход / $0.27 за кэш за 1M (официальный прайс Kimi **−10%**) |
| Ограничение скорости | **не замечено** — всплеск из 30 вызовов ответил 28×200 без единого 429 (остальные два были сбоями прокси) |
| Единица масштабирования | **один аккаунт = один ключ**; кредит живёт на аккаунте, поэтому 10 ключей = 10 × $0.50 |

> 💡 Бесплатный тариф устанавливается Wallaby и может измениться. Проверяйте актуальные цифры на [wallabytoken.com](https://wallabytoken.com) — и пусть собственный шлюз инструмента решает:

```bash
```bash
# каждый ключ в keys.txt: список моделей плюс одно реальное завершение
node src/cli.js --verify-only

# или вручную (ключи не имеют префикса `sk-`)
curl https://api.wallabytoken.com/v1/chat/completions \
  -H "Authorization: Bearer YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"model":"kimi-k3","messages":[{"role":"user","content":"gday"}],"max_tokens":64}'
```

`kimi-k3` — это модель рассуждения: небольшой `max_tokens` расходуется на `reasoning_tokens`, и `content` возвращается как `null`, даже если вызов успешен — именно поэтому этот инструмент считает `content || reasoning_content` доказательством жизни.
```

## 🤖 Модели — все 2 из них

`GET /v1/models` на живом ключе (2026-10-21):

| ID модели | Примечание |
| --- | --- |
| `kimi-k3` | модель, ради которой существует этот провайдер — контекст 1M, открытое рассуждение, мышление тарифицируется как выход |
| `moonshotai/kimi-k3` | та же модель под её вышестоящим id |

Ответы называют обслуживающий стек, а не псевдоним — `"model": "FW-Kimi-K3"` и `"model": "accounts/fireworks/models/kimi-k3"` — значит, бэкенд — Fireworks. Провайдер публикует машиночитаемый прайс-лист на [wallabytoken.com/pricing.json](https://wallabytoken.com/pricing.json).

## 🧪 Как использовать API

Базовый URL **`https://api.wallabytoken.com/v1`** — OpenAI-совместимый, и собственная документация провайдера говорит, что миграция занимает две строки (`base_url` и ключ).

Ключи — **48 символов без префикса `sk-`**; аутентификация — bearer-токен в каждом запросе.

```python
from openai import OpenAI
c = OpenAI(base_url="https://api.wallabytoken.com/v1", api_key="YOUR_KEY")
print(c.chat.completions.create(model="kimi-k3",
      messages=[{"role":"user","content":"gday"}]).choices[0].message.reasoning_content)
```

Документация сайта обещает отсутствие потолка ограничения скорости на бесплатном тарифе; измерение это подтверждает (30 быстрых вызовов, ноль 429, задержки 2–36 с с хвостом на стороне вышестоящего сервиса).

## 🛠 Быстрый старт

```bash
cd wallaby-bulk-apikey
printf 'socks5://host:port\n' > proxies.txt   # необязательно — без него инструмент работает напрямую
node src/cli.js --count 1                    # один аккаунт, от начала до конца, в видимом Chrome
node src/cli.js --count 5 --pool proxies.txt # пять аккаунтов, по одному выходу на каждый
node src/cli.js --verify-only                # заново подтвердить каждый ключ, уже находящийся в keys.txt
```

**Видимый (headful) браузер обязателен** — интерстициал Cloudflare на `/register` не проходит в headless Chrome, и испытание также защищает `POST /api/verification` и `POST /api/user/register`. Поэтому флаг *выключен*: `--headless` существует только для экспериментов.

Ключ записывается в `keys.txt` **только после того**, как `GET /v1/models` и реальное завершение ответили, и каждый аккаунт (почтовый ящик, выход, квота, ключ, доказательство) добавляется в `accounts.json`.

### 🖱️ Лаунчер

Лаунчер запрашивает список прокси (необязательно — без него CLI работает напрямую) и количество аккаунтов, запоминает и то, и другое, и запускает CLI. `--verify-only` заново подтверждает ключи, уже находящиеся в `keys.txt`.

## ✅ Проверено в работе — каждый ключ протестирован

Каждая проверка ниже выполнялась **2026-10-21** через свежие публичные выходы (без VPN в цепочке). Поток создания управлялся закреплённым драйвером лаборатории для первых десяти ключей и **собственным CLI этого пакета от начала до конца для ключа №11**verified**`node src/cli.js --verify-only`**.

| Проверка | Результат |
| --- | --- |
| Интерстициал `/register` в **headful** Chrome | **пройден** — 2–14 раундов кликов, на каждом выходе, который прошёл |
| headless-контроль на тех же выходах | **0/9 прохождений** в тот же час — вот почему флаг по умолчанию выключен |
| локализованное испытание | CF отдаёт интерстициал на языке браузера («Bir dakika lütfen…» на `tr` Chrome, измерено 2026-10-21) → детектор проверяет **корень SPA панели**, а не заголовок, и Chrome закреплён на `--lang=en-US` |
| код из письма | **~15–25 с** от `support@<panel-mail>` («Wallaby邮箱验证邮件»), 6-символьный код, действителен 10 минут |
| `POST /api/user/register?turnstile=` | **200** с `data.access_token` (JWT); токен только в теле отвечает `Turnstile token 为空` |
| сессия консоли | **Bearer JWT** — `/api/user/self` даёт 401 без него, 200 с ним (`quota = 250000`) |
| маршрут ключа | `POST /api/token/` 200 (без ключа в теле) → список возвращает его **замаскированным** → `POST /api/token/<id>/key` возвращает 48-символьный открытый текст |
| `GET /v1/models` на каждый ключ | **200** — `kimi-k3`, `moonshotai/kimi-k3` |
| `POST /v1/chat/completions` на каждый ключ | **200** с `content \|\| reasoning_content` — **11/11 ключей ЖИВЫ** |
| кредит при регистрации | `quota = 250000` = **$0.50**, без карты/телефона/приглашения |
| ограничение скорости | всплеск из 30 вызовов **28×200**, 2 сбоя прокси, **0×429** |
| пропускная способность | **~2–2.5 мин на аккаунт** на хорошем выходе; плохой выход пропускается, в худшем случае ~5 мин |

## 🧭 Как это работает

```
inbox (one address per account)                                  a fresh address per account
   │
   ├─▶ sign-up: Wallaby page → e-mail address → code / link from the inbox
   ├─▶ session: the account's cookies or access token in hand
   ├─▶ key mint: the account's key endpoint → plaintext key returned once (written to disk immediately)
   └─▶ live proof: POST https://api.wallabytoken.com/v1/chat/completions → real content = the key is live
```

| Шаг | Вызов | Примечания |
| --- | --- | --- |
| почтовый ящик | псевдоним temp.tf (`outlook`/`hotmail` plus-alias) | один адрес на аккаунт; панель отклоняет 9 890 одноразовых доменов, а это семейство — настоящий почтовый ящик Microsoft |
| интерстициал | `/register` в **headful** Chrome | виджет находится в закрытом shadow root, поэтому DOM пробивается (`DOM.getDocument {pierce:true}`) и по полю кликают настоящими событиями мыши; 4–10 раундов |
| turnstile | собственный виджет панели (`turnstile_sitekey` из `/api/status`) | считывается нативно, когда страница его решает (токены 773–794 символа), иначе монтируется и кликается в том же ритме |
| код | `GET /api/verification?email=&turnstile=` → код из письма | токен должен идти в **строке запроса**; только в теле маршрут отвечает `Turnstile token 为空` |
| регистрация | `POST /api/user/register?turnstile=` | отправляет 6-символьный код по почте (hex в каждом образце, действителен 10 минут, доставляется за ~15–25 с от `support@<panel-mail>`) |
| сессия | JWT `data.access_token` из register/login | консоль аутентифицируется через **Bearer**, а не cookies: `/api/user/self` отвечает `401 invalid access token` без заголовка |
| ключ | `POST /api/token/` → `POST /api/token/<id>/key` | создание отвечает 200 **без** ключа, а список возвращает его **замаскированным** (`zcMh**********UCAK`); открытый текст приходит только с маршрута `/key` |
| доказательство | `GET /v1/models` + `POST /v1/chat/completions` | напрямую из Node — релей не защищает `/v1/*`; считается `content || reasoning_content` |

## ⚙️ Опции CLI

```bash
node src/cli.js --count N        # accounts to mint (serial)
node src/cli.js --pool proxies.txt
node src/cli.js --proxy socks5://host:port
node src/cli.js --exits K        # exit candidates tried per account
node src/cli.js --model kimi-k3
node src/cli.js --verify-only
node src/cli.js --headless       # NOT recommended — see above
node src/cli.js --help
```

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `--count N` | `1` | сколько аккаунтов создать, по одному браузеру за раз |
| `--pool FILE` | `proxies.txt`, если есть | один выход на строку (`http://`, `socks5://`); без него запуск идёт напрямую |
| `--proxy URL` | — | закрепить один выход |
| `--exits K` | `8` | сколько кандидатов-выходов может израсходовать аккаунт, прежде чем он будет отброшен |
| `--model ID` | `kimi-k3` | модель, используемая для живого шлюза |
| `--port N` | авто | порт Chrome DevTools |
| `--headless` | выкл. | только для экспериментов: Cloudflare не пройдёт |
| `--keep` | выкл. | оставить Chrome открытым по завершении запуска |
| `--code-timeout S` | `360` | сколько ждать код из письма |

## 🛰️ За прокси

**Необязательно — рекомендуется при масштабировании.** Без пула CLI сообщает об этом и подключается напрямую; регистрация, создание ключей и проверка идентичны, меняется только источник пакетов.

С пулом каждая попытка получает **свой собственный браузер, закреплённый за этим выходом** (Chrome фиксирует свой прокси при запуске), поэтому выход, который не может пройти интерстициал, стоит только своей попытки, и CLI переходит к следующему кандидату. Работают те выходы, чей класс IP Cloudflare терпит при видимом браузере; мёртвые линии проявляются как `page-unhealthy-after-clear` или страница `chrome-error` и пропускаются.

Прокси с аутентификацией не поддерживаются браузерной частью — используйте выходы с IP-allowlist. Ротируйте список: лучший выход одного часа часто мёртв на следующий день (измерено 2026-10-21: самый надёжный выход дня перестал отвечать в течение нескольких часов).

## 🔌 Подключение к 9Router

[9Router](https://9router.com) — это самостоятельно размещаемый, OpenAI-совместимый роутер:

```bash
node src/connect-9router.js --base http://localhost:20128 --password 123456
```

Значения по умолчанию: `--prefix wallaby`, `--base-url https://api.wallabytoken.com/v1`, `--model kimi-k3`. Модели обслуживаются как `wallaby/kimi-k3`.

## 🐞 Проблемы

Если Wallaby изменит форму регистрации, свой sitekey Turnstile, маршрут ключа в консоли или каталог, инструмент остановится на этом шаге и сообщит об этом. **[Откройте issue](../../issues)** с командой и точным выводом.
